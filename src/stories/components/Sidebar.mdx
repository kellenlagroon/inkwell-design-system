# Sidebar

The full-height frame for primary product navigation. Pins a `header` and
`footer` around a scrollable `main` region — drop a `Nav` (or anything) into
the main slot.

**Status:** [Beta](?path=/docs/component-status-status--docs) · **Accessibility:** Meets standards

## When to use

- Use `Sidebar` when a product's primary navigation should own the full
  viewport height (typical for admin/console/dashboard shells).
- Prefer a horizontal `Nav` at the top of the page for lightweight or
  content-heavy apps that don't need a persistent nav column.
- Sidebar frames the nav; it doesn't *replace* it. Compose `<Sidebar><Nav
  orientation="vertical" .../></Sidebar>` for the typical shell.

## Usage guidance

- Do keep one `Sidebar` per page — it's the *primary* nav frame, not a
  secondary column.
- Do pair with `<Nav orientation="vertical" />` in the main slot as the
  default composition.
- Don't stack navigation controls in the header/footer slots that duplicate
  the main-slot nav.
- Don't set a fixed body width on top of `fixed` mode — the sidebar leaves the
  layout, so the parent needs its own left/right margin equal to the
  sidebar's width.

## Keyboard and accessibility

- Sidebar renders as `<aside>`. Give the nested `Nav` an `aria-label` (e.g.
  "Primary") so screen readers can identify it.
- The main region is scrollable — focus can enter and exit naturally with
  `Tab`.
