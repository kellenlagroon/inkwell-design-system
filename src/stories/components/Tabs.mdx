# Tabs

A segmented tab bar with a sliding underline indicator, generalizing the app's
submission-type switcher. It's controlled: `Tabs` renders the tablist and reports the
selection through `onChange`; you render the matching panel.

**Status:** [Stable](?path=/docs/component-status-status--docs) · **Accessibility:** Meets standards

## When to use

- Use to switch between a few peer views of the same area (submission types, review statuses, sections).
- Keep the set small and the labels short — this is a horizontal bar, not a nav menu.

## API

<ArgTypes of={TabsStories} />

Pass `tabs` as `{ value, label, disabled? }[]`, plus the controlled `value` and
an `onChange`. Set `id` to wire the tabs to panels: each tab gets
`${id}-tab-${value}` and `aria-controls="${id}-panel-${value}"` — give the panel
that id, `role="tabpanel"`, and `aria-labelledby` the tab id.

## Usage guidance

- Do keep tab labels to one or two words.
- Do render a `role="tabpanel"` region for the selected content and wire it with `id`.
- Don’t use Tabs for primary navigation between pages — that's a nav pattern.

## Keyboard and accessibility

- The tablist uses roving focus: only the selected tab is in the tab order; arrow keys move within it.
- `ArrowRight`/`ArrowDown` and `ArrowLeft`/`ArrowUp` move and activate the next/previous enabled tab, wrapping at the ends.
- `Home`/`End` jump to the first/last enabled tab.
- Each tab is `role="tab"` with `aria-selected`; set `id` so `aria-controls` links each tab to its panel.
