# Select

A custom select control used in both stacked form layouts and tighter control-bar contexts.

**Status:** [Stable](?path=/docs/component-status-status--docs) · **Accessibility:** Meets standards

## When to use

- Use the `form` variant in standard field stacks.
- Use the `control` variant in denser toolbar or header contexts.
- Keep option labels and placeholder text short enough to scan inside the trigger.

## Usage guidance

- Do match the variant to the surrounding layout density.
- Do keep placeholder text descriptive but short.
- Do leave unavailable options visible when that context helps the user.
- Don’t use the control variant as a generic replacement for form fields.
- Don’t overload option labels with long descriptive copy.

## Keyboard and accessibility

- The trigger announces expanded state (`aria-haspopup="listbox"`, `aria-expanded`).
- From the trigger, `ArrowDown` / `ArrowUp` / `Enter` / `Space` open the list with the current selection active.
- In the open list, `ArrowUp` / `ArrowDown` move (skipping disabled options and wrapping); `Home` / `End` jump to the first / last option.
- Type-ahead: typing characters jumps to the option whose label starts with what you typed.
- `Enter` / `Space` choose the active option; `Escape` closes and returns focus to the trigger; `Tab` closes.
- The active selection remains legible without relying on color alone.
- Use a meaningful `aria-label` when the surrounding text does not fully describe the control.
