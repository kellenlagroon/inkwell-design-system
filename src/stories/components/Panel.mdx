# Panel

The default structural surface for grouped content regions across vote, commissioner, and results views.

**Status:** [Stable](?path=/docs/component-status-status--docs) · **Accessibility:** Meets standards

## When to use

- Use `Panel` to define a major content surface.
- Use `SectionHeading` to structure a panel’s internal hierarchy.
- Use `EmptyState` when a panel needs to explain missing data or blocked access.

## Usage guidance

- Do use panels as the default surface for major content blocks.
- Do keep one clear header hierarchy per panel.
- Do place empty-state guidance inside the same panel region the user expects to use.
- Don’t treat `Panel`, `SectionHeading`, and `EmptyState` as unrelated visual fragments.
- Don’t add a separate playground when the value is primarily compositional.

## Keyboard and accessibility

- Panels should preserve heading order so screen readers can scan the page structure.
- Empty states should include clear text guidance rather than relying on styling alone.
