# Surface

The structural surfaces of Inkwell: `Container`, `Center`, `Surface`, `Paper`,
`Panel`, `SectionHeading`, and `EmptyState`. Together they compose page layouts
without leaking custom flex/grid rules.

**Status:** [Beta](?path=/docs/component-status-status--docs) · **Accessibility:** Not reviewed

## When to use

- Use `Container` for page-width constraints.
- Use `Center` for centered auth and empty layouts.
- Use `Surface`/`Paper` for framed panels that are not item cards.
- Use `Panel` as the default surface for a major content region.
- Use `SectionHeading` to structure a panel's internal hierarchy.
- Use `EmptyState` when a panel needs to explain missing data or blocked access.

## Structure primitives

`Panel`, `SectionHeading`, and `EmptyState` ship alongside `Surface` and are
documented here rather than as separate entries. All three accept `className`
(appended, not replacing the base class) and spread any remaining props onto
their root element.

| Component | Element | Props |
|---|---|---|
| `Panel` | `<section>` | `children` |
| `SectionHeading` | `<div>` | `title`, `titleId`, `eyebrow`, `copy`, `compact`, `children` (trailing actions) |
| `EmptyState` | `<div>` | `children` |

`SectionHeading`'s `titleId` is applied to the rendered `<h2>`, which is how
`ModalFrame` resolves `aria-labelledby`. Set it when something outside the
heading needs to reference it.

## Usage guidance

- Do use `Card` for repeated content items and `Panel` for a page's main
  content regions.
- Do keep one clear heading hierarchy per panel.
- Do place empty-state guidance inside the same panel region the user expects
  to use.
- Don't nest cards inside cards for page layout.
- Don't treat `Panel`, `SectionHeading`, and `EmptyState` as unrelated visual
  fragments — they compose together.

## Keyboard and accessibility

- Panels should preserve heading order so screen readers can scan the page
  structure.
- Empty states should include clear text guidance rather than relying on
  styling alone.
