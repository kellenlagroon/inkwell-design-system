# Nav

Primary product navigation with an animated indicator that slides behind the
active item. Renders as a `<nav>` with `<button>` items by default, or `<a>`
when `href` is set. Supports both horizontal and vertical orientation.

**Status:** [Beta](?path=/docs/component-status-status--docs) · **Accessibility:** Meets standards

## When to use

- Use `Nav` for a product's top-level view switch (e.g. Submission / Results / Administrator).
- Prefer `Tabs` when the switcher chooses a panel *within* a page — Nav is for whole-view routing.
- Pass `orientation="vertical"` for a sidebar; `"horizontal"` for a top or bottom bar.
- Pass `mobileDocked` only when the primary horizontal Nav should become a
  fixed bottom bar inside a narrow app container. Inline Navs remain inline by
  default.

### Variants

- **`chip`** (default) — segmented pill with a sliding indicator behind the
  active item. Best for compact horizontal top-nav or a segmented vertical
  switcher.
- **`list`** — full-width rows, tinted-wash active state, sharp corners.
  Tuned for full-height sidebars. Sidebar auto-defaults its nested Nav to
  `list` via context — pass an explicit `variant` to override.

### Item shape

Each item takes the shape:

```ts
type NavItem = {
  value: string;
  label: ReactNode;
  icon?: ReactNode;
  badge?: ReactNode;
  href?: string;
};
```

Items with `href` render as `<a>`; the rest render as `<button type="button">`.
`onChange` fires in both cases so single-page-app routers can intercept the
click.

## Features

### Horizontal

Default. Items sit in a row; the indicator slides on the X axis.

### Equal-width horizontal

Set `equalWidth` when a horizontal Nav fills its container. Each item receives
the same width and its label is centered inside that item.

Equal-width mode also constrains long labels so icon and badge content cannot
force one item wider than its siblings.

### Vertical

Sidebar layout. Items stack; the indicator slides on the Y axis and takes the
item's height.

### List variant

Full-width rows tuned for full-height sidebars: tinted-wash active state,
sharp corners, no sliding indicator. This is what `Sidebar` renders by default.

Optional trailing badge slot. Numbers render as a pill; pass any ReactNode for
custom content. Pass `badge={true}` for a plain notification dot with no

## Usage guidance

- Do keep item labels short — one or two words is ideal.
- Do use the same set of items across every view; changing the item list mid-session breaks recognition.
- Do use the badge slot sparingly — it's for genuinely new or urgent content, not decoration.
- Don't use Nav as a Tabs replacement for content-within-a-page switching; Tabs has the correct ARIA semantics for that.
- Don't stack multiple `Nav`s in the same view — the "primary" nav should live once per page.

## Keyboard and accessibility

- Items are reachable with `Tab`. `Enter` (buttons) or `Enter` (links) activates.
- The wrapping `<nav>` takes `aria-label` — always set it, especially when the page has more than one nav.
- The active item gets `aria-current="page"`; screen readers announce it as the current view.
- Reduced-motion users get an instant indicator swap (no transition).
