# ModalFrame

The shared modal shell. It defines container size, close behavior, heading treatment, and the accessibility wiring (focus trap, Escape, scroll lock, and focus return) around modal structure.

**Status:** [Stable](?path=/docs/component-status-status--docs) · **Accessibility:** Reviewed

## When to use

- Use `ModalFrame` when the interaction needs focused task completion over the current page.
- Use it as a shell around workflow content, not as the workflow itself.
- Keep workflow-specific modal examples in `Patterns/Modals`.

## Usage guidance

- Do match the modal size to the task density.
- Do keep the modal title specific and action-oriented.
- Do reserve larger settings-style shells for configuration-heavy content.
- Don’t mix workflow logic into the frame itself.
- Don’t use a modal when the task would be better served inline.

## Keyboard and accessibility

- On open, focus moves into the dialog (first focusable element, else the card).
- `Tab` / `Shift+Tab` are trapped within the dialog and cycle at the ends.
- `Escape` calls `onClose`, as does clicking the backdrop or the close button.
- Background scroll is locked while the dialog is open.
- On close, focus returns to the element that was focused before opening.
- The dialog is `role="dialog"` with `aria-modal`; pass `titleId` (applied to the heading) so `aria-labelledby` names the dialog, and `describedBy` for supporting copy.
