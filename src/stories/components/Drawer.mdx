# Drawer

A side sheet for focused workflows that should keep page context visible.

**Status:** [Beta](?path=/docs/component-status-status--docs) · **Accessibility:** Not reviewed

## When to use

- Use for edit, inspect, and filter flows that need more room than a popover.
- Use right-side drawers for detail/edit flows and left-side drawers for navigation-adjacent flows.
- Use `ModalFrame` when the task should fully interrupt the page.

### Custom layout

Use `header` to replace the default title-and-close header and `bodyPadding="none"`
when the content needs to own its edge spacing. Provide `ariaLabel` when a custom
header does not include the default title.

## Usage guidance

- Use an outlined `Card` for a nested section. The drawer sits flush with the
  viewport on desktop and uses 12 px top corners in mobile sheet mode.
- Use a wrapping `ActionGroup` for multiple footer actions.
- Do provide a specific title, or `ariaLabel` when using a custom header.
- Do keep close behavior predictable: Escape, backdrop, and close button.
- Don’t put app-specific workflow state in the drawer shell.
- Use `headerClassName`, `bodyClassName`, and `footerClassName` for targeted layout
  hooks rather than overriding Drawer internals.

## Keyboard and accessibility

- The drawer uses `role="dialog"` and `aria-modal`.
- Focus moves into the drawer after it mounts and returns to the opener on close.
- Tab and Shift+Tab wrap at the edges. Escape dismisses a nested Select or
  Popover first when it handles the key.
- If the custom layout has no interactive controls, the panel itself receives focus.
