# Card

A padded content surface for a self-contained unit. Borderless and raised by
default, it is a content-unit sibling to the section-level `Panel`. Compose its
interior with [Stack](?path=/docs/components-stack--docs),
[SectionHeading](?path=/docs/components-surface--docs), and `CardActions` as
needed.

**Status:** [Stable](?path=/docs/component-status-status--docs) · **Accessibility:** Meets standards

## When to use

- Use `Card` for a discrete block of related content that reads as one unit.
- Use [Panel](?path=/docs/components-surface--docs) instead when you want the borderless, raised surface.
- Lay multiple cards out with [Grid](?path=/docs/components-grid--docs) or [Stack](?path=/docs/components-stack--docs).

## API

<ArgTypes of={CardStories} />

`Card` is a surface primitive: it provides padding and surface treatment but no
child layout or spacing. Use `Stack`, `Inline`, or `Grid` inside it to make the
content rhythm explicit. `variant` picks the surface treatment and `tone` flags
destructive zones (they compose). `CardActions` renders a wrapping footer row of
buttons. All pass native `div` props through.

## Features

### Variants

`plain` (default) is borderless on the raised surface — the app's common look.
`outlined` adds a subtle border on the default surface for when there's no
background contrast to rely on.

## Usage guidance

- Do compose a header, body, and actions with `Stack` or another explicit layout primitive.
- Do put the primary and secondary actions in a single `CardActions` footer.
- Do reserve `tone="danger"` for genuinely destructive content.
- Don’t nest cards inside cards — reach for `Panel` or a plain section for inner grouping.

## Keyboard and accessibility

- `Card` renders a plain `div` and adds no semantics; give it a `role`/label if it represents a meaningful region.
- For a clickable/selectable card, render an actual button or link inside (or as the card) — `Card` itself is not interactive.
